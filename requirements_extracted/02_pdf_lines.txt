P001L001: Revised Contact Saving, Excel and Google Sheets
P001L002: Requirements
P001L003: 1. Mandatory Contact Fields
P001L004: A contact can be saved only when the following two fields are available:
P001L005: 1. Name
P001L006: 2. Mobile Number
P001L007: All remaining fields are optional.
P001L008: The application should not save a contact when either the name or mobile number is missing.
P001L009: Validation messages
P001L010: When the name is missing:
P001L011: Name is required. Please enter the contact's name before saving.
P001L012: When the mobile number is missing:
P001L013: Mobile number is required. Please enter a valid mobile number before saving.
P001L014: When both are missing:
P001L015: Name and mobile number are required before this contact can be saved.
P001L016: The user should be able to manually enter missing mandatory information when the AI cannot read it
P001L017: correctly.
P001L018: 2. Mandatory and Optional Columns
P001L019: 2.1 Mandatory Columns
P001L020: The following columns must always be present in the Google Sheet and Excel file:
P001L021: Column Requirement Description
P001L022: Name Mandatory Full name of the person
P001L023: Mobile Number Mandatory Primary contact number

P005L007: 5. Default Append Behaviour
P005L008: After the user saves the first batch, the application should remember the selected destination.
P005L009: For every later upload or scan, the default behaviour should be:
P005L010: Append new contacts to the existing sheet or Excel collection.
P005L011: The application must never overwrite previously saved rows.
P005L012: New contacts must always be added after the last occupied row.
P005L013: Example:
P005L014: Existing data ends at row 125
P005L015: ↓
P005L016: User saves 10 new contacts
P005L017: ↓
P005L018: New contacts are added from row 126 to row 135
P005L019: Rows 1 to 125 must remain unchanged.

P007L007: 8. Google Sheets Append Requirements
P007L008: When saving to an existing Google Sheet, the system should:
P007L009: 1. Identify the configured spreadsheet.
P007L010: 2. Identify the correct worksheet or tab.
P007L011: 3. Locate the last occupied row.
P007L012: 4. Validate that the expected header columns are present.
P007L013: 5. Add new contacts beginning from the next empty row.
P007L014: 6. Preserve all existing rows.
P007L015: 7. Preserve existing formatting where possible.
P007L016: 8. Record the row number used for every contact.
P007L017: 9. Prevent the same contact from being appended twice during retries.

P009L009: 12. Excel Collection Behaviour
P009L010: A browser cannot continuously modify a previously downloaded local Excel file without the user
P009L011: uploading it again.
P009L012: Therefore, the application should maintain an internal contact collection in the database.
P009L013: When the user clicks Download Excel:
P009L014: 1. Retrieve all contacts belonging to the selected collection.
P009L015: 2. Include previous and newly uploaded contacts.
P009L016: 3. Generate a fresh Excel file containing the complete collection.
P009L017: 4. Download the latest version.
P009L018: Example:
P009L019: First upload: 50 contacts
P009L020: Second upload: 20 contacts
P009L021: Third upload: 30 contacts
P009L022: Latest Excel download:
P009L023: 100 contacts
P009L024: The user does not need to manually combine three separate Excel files.

P011L022: Before saving each contact, the application should check:

P011L024: Is Mobile Number present?

P011L026: Is this contact a possible duplicate?

P011L031: • Valid contacts should be saveable.
P011L032: • Invalid contacts should remain under Needs Review.
P011L033: • One invalid card should not block the full batch.

P012L009: 18. Duplicate Mobile Number Handling
P012L010: Because the mobile number is mandatory, it should be the strongest duplicate identifier.
P012L011: Before appending a new row, check:
P012L012: • Same normalised mobile number in the database.
P012L013: • Same mobile number in the current collection.
P012L014: • Same mobile number in the current upload batch.
P012L015: • Same Contact ID already synced to the sheet.
P012L016: When a duplicate is detected, show:
P012L017: A contact with this mobile number already exists.
P012L018: Existing Contact:

P012L020: +91 98765 43210

P013L001: 19. Editing an Existing Contact
P013L002: When an existing contact is edited:
P013L003: • Update the contact in the database.
P013L004: • Do not append it as a new contact.
P013L005: • If it has already been synced to Google Sheets, update its existing row using the saved row
P013L006: reference.
P013L007: • Do not create a new row unless the user explicitly selects Save as New Contact.
P013L008: 20. Safe Retry Behaviour
P013L009: If Google Sheets saving fails after the database save:
P013L010: • Keep the contact safely stored in the database.
P013L011: • Mark Google sync as Failed or Pending.
P013L012: • Retry using the same Contact ID.
P013L013: • Do not append a duplicate row during retry.
P013L014: Example:
P013L015: Contact saved successfully.
P013L016: Google Sheet sync is pending and will be retried.

P014L006: 22. Final Revised Rules
P014L007: 1. Name is mandatory.
P014L008: 2. Mobile Number is mandatory.
P014L009: 3. All other contact fields are optional.
P014L010: 4. Exhibition Name is an additional optional column.
P014L011: 5. Exhibition Date is an additional optional column.
P014L012: 6. New contacts should append to the current collection by default.
P014L013: 7. Existing Google Sheet rows must never be overwritten.
P014L014: 8. New rows should begin after the last occupied row.
P014L015: 9. The user should confirm whether to continue with the existing collection or create a new one
P014L016: after every scan or upload.
P014L017: 10. Continue with Existing Collection should be selected by default.
P014L018: 11. The application should remember the current Google Sheet or Excel collection.
P014L019: 12. Excel downloads should contain the complete collection, including all previous and newly added
P014L020: contacts.
P014L021: 13. Google Sheets and Excel files should always include Name and Mobile Number.
P014L022: 14. Existing contacts should be updated in their original row rather than appended as duplicates.
P014L023: 15. The database should remain the primary source of contact information.
