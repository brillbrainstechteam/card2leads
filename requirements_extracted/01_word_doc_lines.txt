P0001: Business Card Scanner and Contact Management System
P0002: Detailed but Simplified Product Requirement Specification
P0003: 
P0004: 1. Product Overview
P0005: The system will allow users to upload or scan one or multiple business cards.
P0006: The application will:
P0007: Accept business-card images from desktop or mobile.
P0008: Extract contact information using an AI vision model.
P0009: Validate the extracted information.
P0010: Show the extracted information to the user for review.
P0011: Allow the user to correct any field.
P0012: Save the final contact data permanently.
P0013: Allow users to download contacts as an Excel file.
P0014: Allow users to connect their Google account and save contacts to Google Sheets.
P0015: Maintain the original business-card image, extraction status, confidence score and change history.
P0016: Support secure logged-in and logged-out user states.
P0017: The system should prioritise accuracy and should not invent information that is not clearly visible on the business card.
P0018: 
P0019: 2. Product Goals
P0020: The main goals are:
P0021: Reduce manual entry of business-card information.
P0022: Process multiple business cards together.
P0023: Maintain high extraction accuracy.
P0024: Allow users to correct uncertain information.
P0025: Prevent duplicate contacts.
P0026: Save contacts securely.
P0027: Make contact data available across devices.
P0028: Allow easy Excel download.
P0029: Allow direct Google Sheets synchronisation.
P0030: Maintain a clear record of what was uploaded, extracted, edited and exported.
P0031: 
P0032: 3. Recommended Product Approach
P0033: The recommended production design is:
P0034: User uploads business cards
        ↓
Images are stored securely
        ↓
A processing job is created
        ↓
AI extracts card information
        ↓
Validation and duplicate checks are performed
        ↓
User reviews and edits the details
        ↓
Final contact is saved in the database
        ↓
User can:
- Download Excel
- Save to Google Sheets
- View the contact later
- Reprocess the card
P0035: The database should remain the primary source of truth.
P0036: Google Sheets and Excel should be treated as output or integration options, not as the only place where data is stored.

        ↓

        ↓

        ↓
User logs in

Redirect back to /contacts

P0155: 5.4 Session Expiry
P0156: If the session expires while the user is using the application:
P0157: The user should not silently lose unsaved changes.
P0158: The application should show:
P0159: Your session has expired. Please log in again to continue.
P0160: Unsaved edited form data should temporarily remain in browser memory.
P0161: After login, the user should return to the same review screen where possible.
P0162: Uploading or saving should not proceed using an expired session.
P0163: 
P0164: 5.5 Logout Behaviour
P0165: When the user logs out:
P0166: The server session should be invalidated.
P0167: Secure cookies should be cleared.
P0168: Sensitive browser state should be removed.
P0169: Temporary card previews should be removed.
P0170: Permanent saved contacts should remain in the database.
P0171: The user should be redirected to the login or home page.

P0176: Unverified email.
P0177: Expired email-verification link.
P0178: Expired password-reset link.
P0179: Google login permission denied.
P0180: Google account email already registered using password.
P0181: Multiple login attempts.
P0182: Suspicious login activity.
P0183: Disabled account.
P0184: Deleted organisation.
P0185: User removed from organisation.
P0186: Session used from multiple devices.
P0187: Password changed while another session is active.
P0188: Recommended behaviour:
P0189: Invalidate old sessions after password change.
P0190: Rate-limit repeated login attempts.
P0191: Never reveal whether a particular email is registered during password-reset requests.
